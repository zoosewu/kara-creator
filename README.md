# kara-creator — 本機伴唱帶工作室

把 YouTube 影片（或自己的影音檔）做成 KTV 伴唱帶：下載 → 去人聲 → 逐字對時 → 燒上逐字變色的字幕。
全部在本機執行（GPU 加速），附網頁 UI、REST API 與可重做的資料備份。

> 給 AI 助手：先讀 [AGENTS.md](AGENTS.md)（架構、檔案格式、不能破壞的規則、測試方法）。

## 快速開始

```powershell
git clone git@github.com:zoosewu/kara-creator.git
cd kara-creator
.\setup.ps1          # 下載 ffmpeg / deno、建立 Python 環境、取回資料備份（私人 repo，沒有權限會略過）
.\ui.ps1             # 開啟 http://127.0.0.1:8765/
```

需要 Windows、NVIDIA 顯示卡（CUDA 13 驅動）與 Python 3.14（`winget install Python.Python.3.14`）。

三個可以各自獨立執行的步驟：

1. **下載**：用 [yt-dlp](https://github.com/yt-dlp/yt-dlp) 下載影片或音訊
2. **分離**：用 [Demucs](https://github.com/adefossez/demucs) 拆出人聲與伴奏，**輸出格式與來源相同**。
   來源是 mp4 時會保留原影像軌（直接複製、不重新編碼），只換掉音軌。
3. **KTV 字幕**：用 [stable-ts](https://github.com/jianfch/stable-ts)（Whisper）把歌詞逐字對齊到人聲，
   產生逐字變色的字幕並燒進伴奏影片。還沒分離的項目會自動先分離。

每個步驟都會記得做過什麼，重複執行時只處理新的或有變動的項目。

## UI

```powershell
.\ui.ps1          # 啟動後自動開啟 http://127.0.0.1:8765/ ，Ctrl+C 結束
```

- **新增歌曲**：貼上網址，「製作伴唱帶」會下載 → 去人聲 → （有歌詞就）製作伴唱帶；「僅下載」只下載。
  新歌會放進目前選取的曲庫資料夾。
- **曲庫**：樹狀顯示，資料夾可展開 / 收合。
  - 最上方的「新資料夾」建在最上層；每個資料夾列都有「子資料夾」按鈕
  - 拖曳換層級：拖到資料夾中段（虛線框）就放進去，拖到「曲庫」移回最上層；拖到收合的資料夾上停一下會自動展開
  - 拖曳排序（藍色插入線）：歌曲拖到另一首歌的上 / 下半部、資料夾拖到另一個資料夾的上 / 下緣
  - 點資料夾就是選取它，新下載的歌會放進選取的資料夾
- **兩種操作分開呈現**：
  - 藍色外框、有播放圖示的按鈕（去人聲、製作伴唱帶）會排入佇列、實際處理檔案；已完成的步驟不會出現
  - 灰色連結（歌詞、資訊、檔案位置）和最右邊的淺藍色播放鍵只開啟畫面，不會啟動處理
  - 「⋯」選單：重新去人聲、重新對時、檢查對時、全部重做（全部重做會覆蓋手動修改過的字幕檔，會先確認）
- **批次操作**：勾選歌曲（Shift+點可連續勾選）、勾資料夾（含子資料夾的所有歌）或「曲庫」旁的全選，
  上方會出現批次列：
  - 去人聲 / 製作伴唱帶 / 檢查對時：只處理還沒做完的歌，已完成、處理中、缺歌詞的會略過並顯示略過幾首
  - 「重新處理」：重新去人聲、重新對時、重新檢查對時、全部重做，已完成的也會重做
  - 「移動到…」：把勾選的歌移到其他資料夾（先後順序不變）；也可以直接拖曳任一首勾選的歌，整組一起移動或插到別的位置
- **改名**：歌名與資料夾名稱右邊的筆可以直接改（預設填入目前的名稱並全選，方便複製）。
  歌曲輸入「歌手 - 歌名」，Enter 或點別處儲存、Esc 取消、清空還原自動辨識。
- **播放（邊播邊預覽 / 編輯歌詞）**：每首歌最右邊的大播放鍵，預設播放最終輸出的伴唱帶（還沒做好時播放目前最完整的版本，
  按鈕下方會標示）；旁邊的箭頭可以直接選原始影片、伴奏、人聲等其他版本。播放畫面左邊是影片、右邊是歌詞清單：
  - 正在唱的句子會反白並自動捲動；點一句就跳到那句前 1.5 秒
  - 播放原始影片 / 伴奏 / 人聲時，網頁直接畫出逐字填色的字幕（不必等燒錄；日文歌含假名，手動指定的讀音也會反映）；播放伴唱帶成品時字幕已在影片裡，
    一做調整就自動切到伴奏，即時預覽調整後的結果。可切換版本（保留播放位置）、0.5× 慢速
  - 選取的句子與前後各一句會展開工具列（微調 ±0.1 / ±0.5 秒、設為現在、播這句、AI 重對）；只有正在播放的句子會高亮，播放時選取會跟著歌往下走
  - 選一句後按 `Enter`：把這句的開始設成目前播放的位置，並自動選到下一句，可以一路聽一路按
  - `[` `]` 微調 ±0.1 秒（`{` `}` ±0.5 秒），只移選取的這一句；`↑` `↓` 換句、`←` `→` 倒退快轉、空白鍵播放暫停
  - 交給 AI 補完：先把有問題那句的開頭設對（播到開唱的瞬間按 `Enter` 或「設為現在」），再從那句的「AI 重對 ▾」選：
    - 「AI 重對這句及之後全部（N 句）」：以這個開頭為準，只看之後的人聲，把這句到最後一句全部重新對時（約 10–30 秒），之前的句子不動。
      適合 AI 被前奏 / 間奏騙到、從某段開始一路錯下去的情況
    - 「AI 只重對這句」：範圍是這句的開頭到下一句的開頭，只重抓這句每個字的時間（幾秒），適合句子位置對、字的填色不準
    兩者都排進 AI 處理佇列，完成後畫面自動更新並從那句開始播放
  - 點兩下歌詞可以直接修改文字，點左側標籤切換演唱者；時間與歌詞都立刻存檔
  - 改了歌詞文字的話，「更新伴唱帶」會重新對時，手動調整的時間會被取代（畫面上會提醒）；建議先改文字、更新伴唱帶，再回來調時間
  - 還沒製作伴唱帶的歌也能播放並修改歌詞（沒有時間與字幕預覽）
- **對時檢查**：狀態旁出現「⚠ N 句可能不準 / 待確認」時，點它直接開啟播放畫面並跳到第一個有疑慮的句子；
  疑慮句會標底色，用上方的「上一個 / 下一個」或該句的 ⚠ 跳到那句播放。歌詞編輯器裡的 ⚠ 也會直接跳過去。
- **整首重新對時**：曲庫「⋯ → 重新對時」（或批次的「重新處理 → 重新對時」）會像剛填詞時一樣整首重跑 AI 對時，
  手動調整的時間會全部被取代。同樣的歌詞與人聲，結果通常和第一次差不多；某段一路錯的話，用上面的「AI 重對這句及之後全部」比較有效。
- **調整時間**：歌詞編輯器每句最右邊顯示開始時間，點了可以調整這句的開始（只移這一句）；「試聽」從新的開始時間前 1 秒播放人聲確認。
  前面錯、後面通常會自己對回來，所以不提供整段平移；整段偏掉請用播放畫面的「AI 重對這句及之後全部」。
  調整後按「儲存並製作伴唱帶」（或曲庫的「更新伴唱帶」），只會重新產生字幕並燒錄、不會重新對時，並自動重新檢查對時。
  注意：修改歌詞內容會重新對時，手動調整的時間會被取代，所以建議歌詞定案後再調時間；調整時間也會取代用 Aegisub 手動改過的 .ass。
- **歌詞**：曲庫的「歌詞」或播放畫面右上的「完整歌詞」，三種檢視可以隨時切換，按「儲存」後自動關閉：
  - 標註：點標籤切換演唱者（Shift+點套用到整段）、點假名修改讀音
  - 標註原文：含 `[男]` `[女]` `[合]` 與每個漢字讀音 `漢字{よみ}` 的完整原文（自動判斷的讀音也列出，改了就變成手動指定）
  - 原始歌詞：只有歌詞本身，可以直接貼上或修改；沒改到的句子保留演唱者與讀音，改過的句子保留演唱者、讀音重新自動判斷
  - 日文歌詞裡寫在括號中的特殊念法（例如 `運命(さだめ)`、`本気（マジ）`）會在上方提示，按「轉成讀音標註」才轉換：
    括號從歌詞拿掉、讀音變成手動標註（對時也照這個唸法）。只認「漢字緊接著括號、括號裡全是假名」，和聲、英文不受影響
- **資訊**：設定資料夾、歌名、演唱者，會即時預覽輸出檔名；「語言」可以手動指定演唱語言（預設依歌詞文字判斷）。
- **台語 / 粵語歌**：在「資訊」把語言設成台語或粵語，這兩種語言不經 Whisper，整首直接用 CTC 對時，對時檢查只做規則檢查。
  讀音全部手動標：歌詞編輯器「標註」模式裡每個漢字上方都有一個位置，點一下輸入台羅 / 粵拼（聲調符號、數字可有可無），
  按 Enter 會自動跳到下一個字；「標註原文」可以直接寫 `你佇{lí tī}`、`{我|guá}`（羅馬字有幾個音節就標最後幾個字）。
  沒標讀音的字暫用國語拼音代替，對得比較不準。改了語言的歌伴唱帶會顯示需更新（會整首重新對時）。
- **處理佇列 / 執行紀錄**：分成兩條佇列，可看即時紀錄與進度。
  - 下載：只用網路，不必等 AI 處理，最多同時下載 2 首
  - AI 處理：去人聲、對時、檢查對時、燒錄，一次一首（避免搶顯示卡記憶體）
  - 「製作伴唱帶」的新歌先在下載佇列下載，下載完自動移到 AI 處理佇列排隊
  排隊中與處理中的工作可以「取消」：下載、去人聲、燒錄會立刻中斷；對時無法中途打斷，會在對時完成後停下（結果會保留）。
- 亮色 / 暗色：右上角切換，預設跟隨系統。

UI 預設只監聽本機 127.0.0.1；要讓同一個區域網路的其他裝置（手機、其他電腦）也能開，改用 `.\ui.ps1 --lan`，
啟動時會印出可以連的網址（例如 `http://192.168.1.10:8765/`）。開放後同網路的人都能操作曲庫與排入處理；
第一次開放時 Windows 防火牆會詢問，請只允許「私人網路」。處理佇列存在記憶體中，重新啟動 UI 後會清空，但檔案、曲庫與處理狀態都保存在磁碟上。
按一次 Ctrl+C 就會在約 1 秒內關閉：播放中的影片連線直接中斷，處理中的工作會先取消
（Demucs / ffmpeg 子程序一併結束，不會留在背景；已完成的步驟保留，下次重新執行會從沒做完的地方接著做）。
**更新程式後要重新啟動 `ui.ps1` 才會生效。**

## 曲庫與輸出

曲庫的資料夾可以巢狀，順序用拖曳調整（沒有編號）。
完成的伴唱帶會自動輸出到 `output\export\`，資料夾結構與曲庫相同（只用資料夾名稱），
檔名是卡拉 OK 軟體慣用的「歌手 - 歌名」（沒有歌手時只有歌名），可以直接給 karaoke 播放軟體讀取：

```
output\export\zoo\周杰倫\周杰倫 - 最後的戰役.mp4
```

- 同一個資料夾裡歌手與歌名都相同時，依曲庫順序在後面的加上 `(2)`、`(3)`：`周杰倫 - 晴天 (2).mp4`
- 輸出用硬連結，同一顆磁碟不佔額外空間；改名、換資料夾、重新製作後都會自動同步
- 歌名與演唱者的來源：曲庫「資訊」的手動設定 > 歌詞檔的 `# title:` / `# artist:` > 自動辨識
- **自動辨識**（`songtool\titles.py`）不需要設定，也不會蓋掉手動填的內容：
  1. yt-dlp 提供的歌曲資訊（YouTube Music、「- Topic」頻道的影片會有）
  2. 標題規則解析：『』「」《》【】 內的是歌名、前面是演唱者；或「演唱者 - 歌名」；
     去掉 Official MV、HD 等字樣，中英並列時去掉英文譯名（周杰倫 Jay Chou【最後的戰役 The Final Battle】→ 最後的戰役 / 周杰倫）；
     演唱者只留主要歌手，去掉 ft. / feat. 之後的合作歌手（李榮浩 Ronghao Li ft. 張惠妹 → 李榮浩）
  3. 都不符合時整個標題當歌名、頻道名稱當演唱者（這時前奏不顯示標題畫面）
- 曲庫只是整理用的資料（`output\library.json`），不會搬動下載、去人聲等處理用的實體檔案
- 新下載的歌依下載時間排在所在資料夾的最後面，之後可以拖曳調整順序

## 手動放入影片

不是從網址下載的影片或音訊，可以直接放進 `output\downloads\`，UI 開著時幾秒內就會出現在曲庫最上層：

- 直接放在 `output\downloads\` 底下：自動建立「檔名 (local-xxxxxxxx)」資料夾並把檔案移進去
- 放在自己建的子資料夾裡：就地登記，不會搬動
- 歌名與歌手從檔名辨識，用「歌手 - 歌名.mp4」命名最準；也可以之後在「資訊」修改
- 會等檔案複製完（大小 5 秒沒變、沒被其他程式佔用）才匯入；同一個檔案重複放入會略過
- UI 沒開時放入的檔案，下次開 UI 或執行任一 CLI 指令時匯入

## 資料夾結構

```
lyrics\                        ← 歌詞（你提供的輸入）
└── 影片id.txt
output\
├── downloads\                 ← 下載結果（其他步驟的來源）
│   └── 歌名 (影片id)\
│       ├── 歌名.mp4
│       └── download.json      ← 下載紀錄
├── separated\                 ← 分離結果，資料夾名稱與下載資料夾相同
│   └── 歌名 (影片id)\
│       ├── 歌名_vocals.mp4
│       ├── 歌名_instrumental.mp4
│       └── separate.json      ← 分離紀錄
└── karaoke\                   ← KTV 字幕成品
    └── 歌名 (影片id)\
        ├── 歌名_karaoke.mp4   ← 伴奏 + 逐字變色字幕
        ├── 歌名.ass           ← 字幕檔，可手動微調
        ├── alignment.json     ← 逐字時間軸
        └── karaoke.json       ← 製作紀錄
```

## 歌詞：放置位置與寫法

**位置**：`lyrics\<影片id>.txt`，例如 `lyrics\v-WcMQbXbKY.txt`。
影片 id 就是下載資料夾名稱括號內的那串，也可以用 `.\karaoke.ps1 --list` 查看每首歌的歌詞該放在哪裡。

選擇這個位置的原因：

- 歌詞是你提供的**輸入**，和程式產出的 `output\` 分開，清理或重建 `output\` 時不會誤刪
- 用 id 命名，檔名短、不必處理標題裡的特殊字元，重新下載也對得上
- 所有歌詞集中在同一處，好找、好備份

也接受 `lyrics\<下載資料夾名稱>.txt`，或直接放在下載資料夾內的 `.txt`，但建議統一用上面的方式。

**寫法**：

```text
# title: 春の約束
# artist: 歌手名
# 主歌
[女] 窓の外に 小さな花が咲いた
[男] 君の声は 私{わたし}の灯り
[合] {本気|マジ}で 歌おう
```

- UTF-8 編碼；**一行就是畫面上的一句**。放不下畫面寬度的長句會在製作字幕時自動拆成兩句（不縮小字級），
  斷點優先選空白處、其次選換氣處，並讓前後兩半差不多長；想自己決定斷點就在歌詞裡直接換行
- `# title:` / `# artist:` 會在前奏時顯示成標題畫面（可省略）；其他 `#` 開頭的行和空行都會忽略，可以拿來標段落
- 行首 `[男]` / `[女]` / `[合]`：這句由誰唱（可省略）
- `漢字{よみ}`：指定前面連續漢字的讀音；`{原字|よみ}`：明確指定範圍。
  自動判斷的讀音偶爾會錯（例如「私」判成わたくし），指定後對時也會跟著改用正確讀音
- 演唱者：伴唱帶上唱過的字依演唱者變色（男藍、女粉紅、合唱綠），沒標註的句子用預設的藍色
- 讀音：日文歌會在漢字上方顯示假名，並跟著下方的字同步變色；自動判斷的讀音可以在編輯器裡修改
- 這些標記都可以在 UI 的歌詞編輯器裡用點的完成，不必手打
- **照實際演唱順序完整寫出**：重複的副歌要重寫一次，不要寫「×2」或「副歌重複」
- 只留實際唱出來的字：拿掉「作詞：」、`[Chorus]`、括號裡的和聲等
- 歌詞寫錯或漏句會讓前後的對時一起跑掉，這是字幕品質最主要的影響因素

## KTV 字幕

```powershell
.\karaoke.ps1                    # 處理所有有歌詞的下載項目
.\karaoke.ps1 v-WcMQbXbKY        # 用影片 id 或標題關鍵字指定
.\karaoke.ps1 --target both      # 伴奏版（_karaoke.mp4）與原曲版（_lyrics.mp4）都做
.\karaoke.ps1 --list             # 查看狀態
```

| 選項 | 說明 |
| --- | --- |
| `--target` | `instrumental`（預設）/ `original` / `both` |
| `--language ja` | 歌詞語言；預設由歌詞文字判斷（有假名 → 日文，有漢字 → 中文） |
| `--font "Yu Gothic"` | 字型；預設日文用 Yu Gothic、中文用微軟正黑體 |
| `--model large-v3` | 對時用的 Whisper 模型 |
| `--realign` | 強制重新對時 |
| `--force` | 全部重做，**會覆蓋手動修改過的 `.ass`** |

**對時方式**（`songtool\align.py`）：

1. stable-ts（Whisper large-v3 + VAD）決定每一句大致的位置
2. 用人聲軌音量修正句子層級的錯誤（整句落在前奏、字被放到遠處、上一句的長音被算進下一句等），
   修正內容會顯示在執行訊息裡
3. MMS 多語言模型做 CTC 強制對齊，重新定出句內每個音的起點。日文讀音用 MeCab 依上下文判斷，中文用拼音。
   同時做「整段」（緊接的句子一起對齊，擅長慢板重複的副歌）與「逐句」（擅長快歌）兩種，每句挑比較可信的結果
4. 字與字之間人聲沒斷（長音）時，填色一路延續到下一個字

製作字幕時，放不下畫面寬度的長句會拆成兩句；字寬用實際字型量測（Pillow），日文假名也依此定位。

**對時檢查**（`songtool\qa.py`，全部在本機，不需要網路）：製作伴唱帶的最後會自動執行，約 20～30 秒；
舊的歌可以從「⋯ → 檢查對時」補做。結果存在 `output\karaoke\<名稱>\qa.json`，對時改變後自動失效。

1. 規則：句首的字唱得比同句其他字慢很多、好幾個字連續一閃而過、整句大多落在沒有人聲的地方（一般長音不算）
2. 獨立聽寫：用同一個 Whisper 模型、不看歌詞逐段聽寫人聲，以音節比對每個字的起點
   - 與聽寫差 1.5 秒以上：**可能不準**
   - 規則有疑慮、聽寫也無法確認：**待確認**
   - 規則有疑慮但聽寫吻合：不標

聽寫本身在長音附近約有 ±1 秒誤差，所以門檻訂得保守，只抓明顯的錯；一句裡只有中間幾個字錯的情況可能抓不到。

第一次執行會下載 Whisper large-v3（約 3GB）與 MMS 對齊模型（約 1.2GB）。

**手動微調**：用 [Aegisub](https://aegisub.org/) 等工具打開 `.ass` 修改時間後存檔，再跑一次 `.\karaoke.ps1`，
只會重新燒錄影片，不會覆蓋你的修改。修改歌詞檔則會重新對時並重新產生 `.ass`。

## 使用

```powershell
# 下載（網址帶 list= 也只會下載該支影片）
.\download.ps1 "https://www.youtube.com/watch?v=..."
.\download.ps1 URL1 URL2 URL3
.\download.ps1 --batch urls.txt          # 每行一個網址，# 開頭為註解
.\download.ps1 URL --audio-only          # 只要音訊（m4a，不轉檔）
.\download.ps1 PLAYLIST_URL --playlist   # 整個播放清單

# 分離
.\separate.ps1                           # 處理所有尚未分離的下載項目
.\separate.ps1 "D:\music\song.mp4"       # 直接處理任意檔案或資料夾

# 查看狀態（兩個指令都可以）
.\separate.ps1 --list
```

## 如何判斷「做過了」

| 步驟 | 判斷方式 | 會重做的情況 |
| --- | --- | --- |
| 下載 | `download.json` 內的網站與影片 id（不同網址寫法指向同一支影片也認得） | 媒體檔被刪除、加 `--force` |
| 分離 | `separate.json` 記錄來源檔大小與修改時間、分離參數、輸出檔清單 | 來源檔變動、參數不同（例如改 `--stems 4`）、輸出檔被刪除、加 `--force` |
| KTV 對時 | `alignment.json` 記錄歌詞內容雜湊、人聲檔、模型、語言 | 歌詞修改、重新分離、改模型或語言、加 `--realign` |
| KTV 燒錄 | `karaoke.json` 記錄 `.ass` 內容雜湊與來源影片 | `.ass` 被修改、來源影片變動、成品被刪除 |

紀錄檔都在工作完成後才寫入，中途失敗或被中斷的項目下次會自動重做。
改變參數重跑時，上一次留下、這次不會產生的檔案會被清掉（例如從 4 軌改回 2 軌）。

直接指定 `output\downloads\` 以外的檔案時，輸出資料夾使用檔名，例如 `output\separated\song\`。

## 分離選項

| 選項 | 說明 |
| --- | --- |
| `--stems 4` | 拆成 `drums` / `bass` / `vocals` / `other` 四軌（預設 2 軌：`vocals` / `instrumental`） |
| `--model htdemucs_ft` | 微調模型，品質略好但約慢 4 倍（預設 `htdemucs`） |
| `--format mp3` | 強制輸出格式（輸出音檔時不含影像） |
| `--shifts 2` | 多次隨機位移取平均，品質略升、時間成比例增加 |
| `--device cpu` | 不用 GPU（預設 `auto`） |
| `--force` | 忽略紀錄，強制重做 |

## 資料備份與重做

影片、伴奏、伴唱帶都有版權也很大，**不進任何 git repo**。能重做一次的資料放在 `data\`，
它本身是另一個**私人** repo（`kara-creator-data`）的 clone，公開的程式 repo 完全不包含它：

| 檔案 | 內容 |
| --- | --- |
| `data\songs.json` | 曲庫資料夾、每首歌的歌名 / 演唱者 / 語言、影片連結與來源資訊 |
| `data\lyrics\<id>.txt` | 歌詞（含演唱者標籤與手動讀音） |
| `data\timing\<id>.json` | 對時結果（含手動調整與 AI 重對） |

- **自動備份**：佇列清空時、或曲庫 / 歌詞 / 時間有變動且安靜 30 秒後，UI 會寫出 `data\`、commit 並 push
  （紀錄在處理佇列的「收尾」）。push 失敗只記錄，下次會再試。手動補一次：`python scripts\backup.py`。
- **重做**：`python scripts\restore.py --make`：建立資料夾與歌曲資訊、重新下載有連結的影片、放回歌詞與對時，
  接著去人聲並製作伴唱帶。**對時直接沿用備份**（不重新對時，手動調過的時間都保留）。
- 手動放入的影片沒有連結：`restore.py` 會列出原始檔名與大小，把同一個檔案放回 `output\downloads\` 再執行一次即可
  （id 由檔名與大小決定，放回同一個檔案就對得上）。

## 收尾 hook（例如 rsync 同步伴唱帶）

佇列清空（或曲庫有變動、安靜 30 秒後）會在備份之後執行 `hooks\on_idle.ps1`。
把 `hooks\on_idle.example.ps1` 複製成 `on_idle.ps1` 再修改（`on_idle.ps1` 不進 git）。
可用的環境變數有 `SONG_HOOK_REASON`、`SONG_EXPORT_DIR`（伴唱帶成品）、`SONG_HOOK_SUMMARY`（這一輪的結果 JSON）、
`SONG_JOBS_DONE` / `SONG_JOBS_FAILED` 等，說明見範例檔。輸出顯示在處理佇列的「收尾」紀錄裡。

## REST API（給其他服務串接）

`/api/v1` 是給外部服務用的 REST API（網頁 UI 目前用 `/api` 底下的舊端點）：

- 一首歌只有一個 id（影片 id，或手動放入檔案的 `local-xxxxxxxx`）；PATCH 只改有給的欄位
- 會花時間的處理都是「工作」：建立時回 `202` 與 `Location: /api/v1/jobs/{id}`
- `GET /api/v1/events` 是 Server-Sent Events：`job`（工作狀態變化）、`idle`（佇列清空）、`library`（曲庫變動）
- 設了環境變數 `SONG_API_TOKEN` 時要帶 `Authorization: Bearer <token>`（開 `--lan` 時建議設定）
- 完整規格與線上測試：啟動後開 `http://127.0.0.1:8765/docs`；端點總覽見 `ui\api_v1.py` 開頭

```powershell
# 例：給網址，一路做到伴唱帶
curl -X POST http://127.0.0.1:8765/api/v1/songs -H "Content-Type: application/json" -d '{"url": "https://youtu.be/..."}'
```

## 程式結構

核心邏輯都在 `songtool\` 套件，CLI 只負責解析參數與顯示，日後的 UI 可以直接呼叫同一套函式：

| 模組 | 內容 |
| --- | --- |
| `songtool\download.py` | `download(urls, ...)` 逐項 yield 結果；`list_downloads()`；`progress_hooks` 可接 UI 進度條 |
| `songtool\separate.py` | `separate_file(src, SeparateOptions, log=...)`；`log` 可導向 UI |
| `songtool\library.py` | `scan()` 回傳每個下載項目與其分離狀態 |
| `songtool\karaoke.py` | `make(item, KaraokeOptions, log=...)`；`status(item)` 回傳 `no_lyrics` / `pending` / `done` / `outdated` |
| `songtool\lyrics.py` | 歌詞尋找（`find` / `candidates`）與解析 |
| `songtool\align.py` | 逐字對時：Whisper 定句 → 音量修正 → CTC 逐音精修 |
| `songtool\reading.py` | 把一句歌詞切成變色單位並附羅馬字讀音；`furigana()` 給編輯器顯示假名 |
| `songtool\catalog.py` | 曲庫：巢狀資料夾、排列順序、歌名與演唱者（`output\library.json`） |
| `songtool\local.py` | 手動放進 `output\downloads\` 的影音檔自動登記成曲庫項目 |
| `songtool\export.py` | 依曲庫把完成的伴唱帶同步到 `output\export\` |
| `songtool\jobs.py` | 背景工作佇列（下載 / AI 處理兩條，模型常駐）；佇列清空時呼叫 `on_idle` |
| `songtool\backup.py` | 資料備份：`snapshot()` 寫出 `data\`，`publish()` commit + push |
| `songtool\hooks.py` | 收尾 hook（`hooks\on_idle.ps1`）與變動後的延遲觸發 |
| `songtool\demucs_run.py` | Demucs 人聲分離（流程同 `demucs.separate`，用 soundfile 存檔） |
| `ui\server.py` | FastAPI 後端；`ui\static\` 為前端（原生 HTML/CSS/JS，不需打包） |
| `ui\api_v1.py` | REST API v1（給其他服務串接） |
| `songtool\ass.py` | 逐字時間軸 → KTV 版面的 ASS 字幕；`Style` 可調顏色、字型、提前出現秒數等 |
| `songtool\config.py` | 路徑設定；環境變數 `SONG_OUTPUT_DIR` 可改變輸出根目錄 |

## 環境

`setup.ps1` 會建好全部。手動重建 Python 環境時：

```powershell
py -3.14 -m venv .venv
.\.venv\Scripts\python.exe -m pip install torch==2.11.0 torchaudio==2.11.0 --index-url https://download.pytorch.org/whl/cu130
.\.venv\Scripts\python.exe -m pip install -r requirements.txt -c constraints.txt
```

Python 3.14 + PyTorch 2.11（CUDA 13.0）。torchaudio 最新只到 2.11、只支援到 Python 3.14，所以目前停在 3.14。
torchaudio 2.9 起存音檔需要另外安裝 torchcodec，所以 Demucs 改由 `songtool\demucs_run.py` 執行
（分離流程和 `demucs.separate` 相同，只是用 soundfile 存檔），不需要 torchcodec。

`tools\` 內放專案自帶的外部工具，不需加進系統 PATH：

- `tools\ffmpeg\bin\`：ffmpeg / ffprobe
- `tools\deno\`：yt-dlp 解析 YouTube 需要的 JavaScript runtime

YouTube 常改版，下載失敗時先更新 yt-dlp：

```powershell
.\.venv\Scripts\python.exe -m pip install -U "yt-dlp[default]"
```
